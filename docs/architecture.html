1 · Overview

What it is

A knowledge base for one project or client area. People add sources (documents, tickets, meeting recordings, e-mails, code). The model reads every source completely and writes the wiki: source summaries, pages about systems, rules, processes and decisions, linked to each other, with every statement citing the exact page, minute, comment or line it comes from. People then ask questions in plain language (in Copilot CLI, the terminal or a local browser app); the model answers from the wiki, and when needed from the original sources, the code, Jira and screenshots.

The model is the author

Karpathy's LLM Wiki pattern, as in the claude-obsidian plugin. No fixed fact templates.

Scripts are the guard

Sandbox, text extraction with locators, checks, commits, rollback, metering.

Every statement has a source

Citations to page / minute / comment / line; originals never change.

Local and private

Runs on the work laptop, no admin rights; the knowledge stays in a local Git repository.

6 · End users

How people interact with it

Specialist / newcomer: asks

  • Copilot CLI in the repo folder: plain question or /kb-ask.
  • kb serve → Discuss: a topic, follow-up questions, Ctrl+V a screenshot, click citations.
  • Answer in a few sentences, each with its source; NOT FOUND instead of guessing.

Curator: feeds and looks after the wiki

  • kb serve → Add sources: drop files, watch the model read and write, Cancel.
  • kb remove, kb lint, kb verify, kb quota.
  • Reviews the Git diff after an ingest.

Developer: code questions

  • kb code-ask "…" --evidence or /kb-code; "question about the code" in Discuss.
  • Wiki + code + Jira in one answer, cited to file:line@commit.

Manager: state at a glance

  • Dashboard: sources, pages, contradictions, citation check, premium requests, recent questions.
  • Opens offline from one HTML file; optional logo from instance\branding\.

9 · Security and data

Controls

Sandbox for the model

Allowed tools only; read inside the instance (and configured repositories); write only in wiki/; questions are read-only; denied calls are logged and counted in the commit.

Sources are data

Prompts say so explicitly; even if a document contains instructions, the model cannot run commands or reach the network.

Secrets

Only in Windows Credential Manager; the pre-commit hook blocks tokens and keys in both repositories.

Local app

kb serve listens on 127.0.0.1 only and needs a per-start token, so other web pages cannot call it.

Traceability

Originals unchanged; one commit per change with model and cost; every page change visible as a diff.

Removal and history

kb remove deletes the current files, but the instance's Git history still contains them. True erasure needs a history rewrite (not built).

12 · Easy to forget

Questions this architecture still has to answer

Who reviews the model's pages?

Pages stay draft. Without a review habit (owner per area, diff after each ingest), errors accumulate silently.

New version of a document

A changed file gets a new id and is ingested as a new source. The model may notice it supersedes the old one, but there is no explicit "supersedes" step yet.

Prompt changes

Prompts shape the whole wiki. Their version is not recorded in commits yet; after a prompt change, older pages follow older rules.

Model upgrade

A stronger model can re-ingest the same sources. Decide whether to rebuild the wiki from scratch or let the new model update existing pages.

Backup

The instance is a local Git repository plus store\ (not in Git). A copy to a company share or a company Git server is not set up.

Two writers at once

kb serve locks within its own process only. Running kb ingest in a terminal at the same time can conflict; use one at a time.

Language

The wiki is in English; sources may be Polish. The model translates when writing; quotes in the original language are not enforced.

Erasure

Removing a source does not remove it from Git history (see section 9).
